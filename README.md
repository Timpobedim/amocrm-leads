# Заявки с сайта в amoCRM — приёмник формы, очередь и OAuth без потерь

Языковая школа принимает на сайте заявки на пробный урок. Приёмник на FastAPI проверяет форму (телефон,
e-mail, согласие на обработку персональных данных по 152-ФЗ), сохраняет заявку в очередь и сразу
отправляет в amoCRM: ищет контакт по телефону, чтобы не плодить дубли, создаёт сделку с контактом одним
запросом и добавляет примечание с комментарием и UTM-метками. Если amoCRM недоступен или упёрся в лимит,
заявка не теряется — её дошлёт фоновая задача. Двойной клик по кнопке «Отправить» не создаёт две заявки.

**Стек:** Python 3.12 · FastAPI · httpx (async) · pydantic v2 · SQLite · OAuth 2.0 · pytest +
pytest-asyncio · ruff · mypy (strict) · uv.

## Доставка без потерь

- **Очередь (outbox).** Заявка сохраняется в SQLite до отправки. Ответ сайту: 201 — заявка уже в
  amoCRM, 202 — принята и уйдёт позже, 200 — повтор уже принятой. Временные ошибки (сеть, 429, 5xx,
  токен) — новая попытка через 1, 5, 15, 60 минут, дальше раз в час. Отказ amoCRM по данным (4xx) —
  статус `failed`, заявку разбирает человек.
- **Идемпотентность.** Ключ — хеш телефона, курса и даты (или заголовок `Idempotency-Key` от сайта):
  двойной клик и повторная отправка формы в тот же день дают одну заявку.
- **Без дублей контактов.** Контакт ищется по телефону; `query` в amoCRM ищет по подстроке, поэтому
  совпадение проверяется ещё раз по последним десяти цифрам. Найденный контакт привязывается к сделке по id.
- **Сделка не создаётся дважды.** Номер сделки пишется в очередь сразу после создания: если потом не
  добавилось примечание, повтор добавит только его.
- **OAuth с одноразовым refresh-токеном.** Access-токен живёт сутки, refresh-токен — три месяца и
  обменивается один раз. Обновление идёт под `asyncio.Lock` — пять одновременных 401 дают одно обновление
  (тест `test_concurrent_rejections_refresh_the_token_once`). Токен обновляется заранее, за минуту до
  истечения, а новая пара атомарно пишется на диск. Второй процесс со старым файлом токенов получил бы
  отказ, поэтому приёмник запускается одним процессом, а тест
  `test_second_process_with_a_stale_token_file_is_told_to_reauthorize` проверяет, что такая ситуация
  объясняется, а не ломает интеграцию молча. Для частной интеграции проще долгосрочный токен
  (`AMO_LONG_LIVED_TOKEN`, срок от суток до пяти лет).
- **Ошибки формы — по-русски и по полям:**
  `{"errors": {"phone": "Телефон нужен российский мобильный, например +7 900 123-45-67"}}`.

## Как это выглядит

```bash
curl -X POST http://127.0.0.1:8000/forms/trial -H "Content-Type: application/json" -d '{
  "name": "Мария", "phone": "8 (900) 123-45-67", "email": "maria@example.ru", "course": "english",
  "comment": "Удобно по вечерам", "consent": true, "utm_source": "yandex", "utm_campaign": "autumn"}'
```

```json
{"status": "sent", "lead_id": 1002, "duplicate": false}
```

В amoCRM появляются сделка «Пробный урок: Английский» с тегами «Сайт» и «Английский», контакт «Мария» с
телефоном +79001234567 и e-mail и примечание:

```text
Заявка с сайта: пробный урок, английский
Имя: Мария; телефон: +79001234567; e-mail: maria@example.ru
Комментарий: Удобно по вечерам
UTM: source=yandex, campaign=autumn
```

## Быстрый старт

```bash
uv sync --group dev
cp .env.example .env    # AMO_BASE_URL и AMO_LONG_LIVED_TOKEN (или OAuth: AMO_CLIENT_ID… и `amo-leads authorize <код>`)
uv run amo-leads serve --port 8000
```

`GET /health` показывает очередь: `{"status": "ok", "queue": {"pending": 0, "sent": 12, "failed": 0}}`.
Дослать заявки вручную (например, из cron) — `uv run amo-leads retry`.

## Структура

```text
src/amo_leads/
├── app.py        # FastAPI: POST /forms/trial, GET /health, фоновая досылка
├── forms.py      # форма пробного урока, сделка и примечание для amoCRM
├── outbox.py     # очередь заявок в SQLite
├── delivery.py   # отправка: контакт по телефону → сделка → примечание
├── client.py     # клиент amoCRM API v4: параметры, темп, страницы, повторы
├── tokens.py     # OAuth 2.0 с одноразовым refresh-токеном и долгосрочный токен
├── settings.py   # настройки из .env
├── cli.py        # serve, authorize, retry
└── testing.py    # эмулятор нужной части amoCRM
tests/            # 31 тест
```

## Как проверялось

Windows 10, Python 3.12 (uv):

- `ruff check`, `ruff format --check`, `mypy` (strict, 11 файлов) — без ошибок;
- `pytest` — 31 тест: клиент (9), токены (7), форма (9), приёмник целиком через `TestClient` и эмулятор
  amoCRM — новый и известный клиент, двойной клик, недоступность amoCRM с досылкой из очереди, отказ по
  данным, ошибки полей (6).

Не проверялось: живой amoCRM — нужен аккаунт с интеграцией. Эмулятор повторяет документированное:
`POST /oauth2/access_token` и одноразовый refresh-токен, 401 при истёкшем токене, 429 при превышении 7
запросов в секунду, ответ 204 для пустого списка, `/api/v4/leads/complex`, примечания. Формат ошибок
валидации и поиск контактов по телефону на реальном сервере не сверялись.
